# 비밀번호 · 통신 보안 가이드

이 문서는 나름 대관 시스템의 **비밀번호 보안**과 **통신 암호화(HTTPS)** 설정을
비전공자도 이해할 수 있게 쉽게 설명합니다.

---

## 1. 한눈에 보는 결론

| 구분 | 현재 상태 | 해야 할 일 |
| --- | --- | --- |
| **비밀번호 저장** | ✅ 이미 안전 (암호화 해시) | 없음 |
| **통신 (개발용, HTTP)** | ⚠️ 노출 위험 있음 | 개발 중엔 그대로 OK |
| **통신 (실제 배포)** | ❌ 반드시 HTTPS 필요 | 아래 3번 따라 설정 |

> 핵심: **비밀번호 저장은 이미 안전합니다.** 신경 쓸 부분은 "배포할 때 HTTPS를
> 켜는 것" 하나입니다.

---

## 2. 비밀번호는 어떻게 저장되나요?

입력한 비밀번호를 그대로 저장하지 않고, **되돌릴 수 없는 형태(해시)** 로 바꿔서
저장합니다.

```
사용자가 입력:  manage123
DB에 저장되는 값:  pbkdf2:sha256:600000$abc...   ← 원래 비번을 알 수 없음
```

- 로그인할 때는 "입력한 비번을 같은 방식으로 바꿔서, 저장된 값과 같은지" 만 비교합니다.
- 그래서 **DB가 유출돼도 원래 비밀번호는 알 수 없습니다.**
- 사용하는 방식: `werkzeug`의 `pbkdf2` (널리 검증된 표준 방식)

👉 이 부분은 **이미 잘 되어 있어 손댈 필요가 없습니다.**

---

## 3. 통신은 왜 HTTPS가 필요한가요?

비밀번호는 저장은 안전하지만, **인터넷을 타고 서버로 갈 때(전송 중)** 는 보호가
필요합니다.

- **HTTP** (자물쇠 ❌): 편지를 봉투 없이 보내는 것. 중간에서 누구나 볼 수 있음 →
  비밀번호가 그대로 노출.
- **HTTPS** (자물쇠 🔒): 편지를 잠긴 상자에 넣어 보내는 것. 중간에서 못 봄.

> 💡 **자주 하는 오해:** "프론트에서 자바스크립트로 비번을 암호화해서 보내면
> 되지 않나?" → HTTP 위에서는 공격자가 그 암호화 코드 자체를 바꿔치기할 수 있어
> 소용이 없습니다. **정답은 무조건 HTTPS입니다.**

## 4. 설정 항목 설명 (`.env` 파일)

설정은 코드를 고치지 않고 `.env` 파일(또는 환경변수)로 켜고 끕니다.
**개발 중엔 기본값 그대로 두면 되고, 배포할 때만 바꾸면 됩니다.**

### 개발용 (지금 상태 — 그대로 두세요)

```bash
SESSION_COOKIE_SECURE=false   # 쿠키를 HTTP에서도 허용 (개발 편의)
FORCE_HTTPS=false             # HTTPS 강제 안 함
TRUSTED_PROXY_HOPS=0          # 프록시 없음
HSTS_MAX_AGE=0                # HSTS 미사용
```

### 실제 배포용 (HTTPS를 붙인 뒤 켜세요)

```bash
SESSION_COOKIE_SECURE=true    # 로그인 쿠키를 HTTPS로만 전송
FORCE_HTTPS=true              # HTTP로 오면 HTTPS로 자동 전환
TRUSTED_PROXY_HOPS=1          # nginx 같은 프록시 뒤라면 1 (없으면 0)
HSTS_MAX_AGE=31536000         # "이 사이트는 항상 HTTPS" 를 1년간 기억
```

### 각 항목 뜻

| 항목 | 뜻 | 언제 켜나 |
| --- | --- | --- |
| `SESSION_COOKIE_SECURE` | 로그인 유지용 쿠키를 HTTPS에서만 보냄 | 배포 시 `true` |
| `FORCE_HTTPS` | 실수로 HTTP로 접속해도 HTTPS로 자동 이동(301) | 배포 시 `true` |
| `TRUSTED_PROXY_HOPS` | nginx 등 앞단 프록시가 몇 개인지 (보통 1) | 프록시 있으면 `1` |
| `HSTS_MAX_AGE` | 브라우저에게 "앞으로도 HTTPS만 써라" 지시(초) | **안정화 후** `31536000` |
| `HSTS_INCLUDE_SUBDOMAINS` | 서브도메인까지 HTTPS 강제 | 필요 시 `true` |
| `ENABLE_SECURITY_HEADERS` | 아래 6번 보안 헤더 on/off | 기본 `true` 유지 |

> ⚠️ **HSTS 주의:** `HSTS_MAX_AGE`를 켜면 브라우저가 "이 도메인은 HTTPS만" 이라고
> 기억해서, 나중에 HTTP로 돌아갈 수 없게 됩니다. **HTTPS가 확실히 안정적으로
> 동작하는 걸 확인한 뒤에** 켜세요.

## 5. 배포할 때 실제로 하는 일

TLS(HTTPS 인증서)는 보통 **앱이 아니라 앞단의 웹서버(nginx 등)** 가 처리합니다.
흐름은 이렇습니다:

```
[사용자 브라우저] --HTTPS(암호화)--> [nginx: 인증서 처리] --HTTP--> [Flask 앱]
```

1. 도메인 준비 (예: `booking.example.com`)
2. nginx/Caddy 같은 웹서버 앞에 두고, **무료 인증서(Let's Encrypt)** 로 HTTPS 적용
3. 그 웹서버가 요청을 Flask 앱(내부 HTTP)으로 넘김
4. `.env`에서 위 "배포용" 설정을 켬 (특히 `TRUSTED_PROXY_HOPS=1`)

> `TRUSTED_PROXY_HOPS=1`을 켜야 앞단 nginx가 "이건 HTTPS로 들어온 요청" 이라고
> 알려주는 정보를 Flask가 신뢰합니다. 그래야 `Secure` 쿠키가 제대로 동작합니다.

## 6. 자동으로 추가되는 보안 헤더

`ENABLE_SECURITY_HEADERS=true`(기본값)이면 모든 응답에 아래가 자동으로 붙습니다.
특별히 설정할 건 없고, 참고용입니다.

| 헤더 | 하는 일 (쉽게) |
| --- | --- |
| `X-Content-Type-Options: nosniff` | 브라우저가 파일 종류를 멋대로 추측하지 않게 함 |
| `X-Frame-Options: DENY` | 다른 사이트가 우리 페이지를 몰래 끼워넣지 못하게 함(클릭 가로채기 방지) |
| `Referrer-Policy: no-referrer` | 다른 사이트로 이동할 때 우리 주소 정보를 흘리지 않음 |
| `Strict-Transport-Security` | (HTTPS일 때만) "항상 HTTPS 써라" 지시 — HSTS |

## 7. 로컬에서 HTTPS를 테스트하고 싶다면

개발 PC에서 HTTPS 동작을 미리 확인하고 싶을 때:

```bash
pip install cryptography      # 최초 1회
DEV_HTTPS=true python app.py  # https://127.0.0.1:8000 로 실행
```

- 자체서명 인증서라서 브라우저가 "안전하지 않음" 경고를 띄웁니다 → 테스트니까 무시하고 진행.
- 실제 배포에는 쓰지 마세요(5번의 정식 인증서 사용).

## 8. 자주 묻는 질문

**Q. 지금 비밀번호가 평문으로 저장돼 있나요?**
A. 아니요. 이미 해시(pbkdf2)로 저장돼 있어 안전합니다.

**Q. 그럼 뭘 더 해야 하나요?**
A. 실제 배포 시 **HTTPS를 켜는 것** 하나면 충분합니다(3~5번).

**Q. 개발 중에도 HTTPS를 켜야 하나요?**
A. 아니요. `localhost` 개발은 HTTP로 충분합니다. 기본값 그대로 두세요.

**Q. 설정을 바꾸면 코드도 고쳐야 하나요?**
A. 아니요. `.env` 값만 바꾸면 됩니다. 코드 수정 불필요.
